# 🏗️ Архитектурный обзор neira-code-analyzer

**Версия: 2.0 (Декабрь 2024)**

Этот документ описывает обновленную архитектуру `neira-code-analyzer` после внедрения интерактивной модели анализа и перехода на асинхронные операции.

## 📋 Принципы архитектуры

В основе обновленной архитектуры лежат следующие принципы:

- **🧠 JSON API Contract:** Строгое определение формата взаимодействия с ИИ через JSON-схемы. Обеспечивает предсказуемость, надежность и возможность валидации ответов.
- **🛡️ Fail-Fast:** Система немедленно прерывает работу при критических ошибках конфигурации, предотвращая "тихие отказы" и облегчая диагностику.
- **🔄 Асинхронность:** Все операции ввода-вывода, особенно вызовы к AI-моделям, выполняются асинхронно, что исключает блокировку event loop и повышает производительность.
- **🎯 Single Responsibility Principle (SRP):** Каждый компонент имеет одну, четко определенную зону ответственности.
- **🔌 Dependency Injection:** Зависимости предоставляются компонентам извне, что упрощает тестирование и повышает модульность.

## 🏢 Структура модулей

### 🧠 Интерактивная модель анализа (Core)

Это ядро новой архитектуры, обеспечивающее интерактивное взаимодействие с ИИ.

- **`AnalysisAgent`**: Главный оркестратор. Управляет логикой сессии, формирует промпты для ИИ, обрабатывает структурированные JSON-ответы и координирует работу других компонентов.
- **`AnalysisSessionManager`**: Управляет жизненным циклом и состоянием сессий анализа. Отвечает за сохранение, загрузку и кеширование контекста диалога.
- **`AnalysisActionExecutor`**: Безопасный исполнитель действий, предложенных ИИ. Обрабатывает команды (`create_file`, `update_file` и т.д.), создает бэкапы и позволяет откатывать изменения.
- **`BaseSessionManager`**: Абстрактный базовый класс, предоставляющий общую логику для всех менеджеров сессий и устраняющий дублирование кода.

### 📡 Слой MCP (Model Context Protocol)
- `main.py`: Точка входа MCP-сервера. Обрабатывает запросы от клиента.
- `mcp_schemas.py`: Определяет JSON-схемы для всех инструментов, доступных через MCP, включая параметры для интерактивных сессий (`user_query`, `session_id`).

### 🔧 Вспомогательные сервисы
- `ai_utils.py`: Содержит асинхронную функцию `generate_ai_review_async` для неблокирующих вызовов к Google Gemini API.
- `context_generator.py`: Отвечает за сбор и форматирование контекста кодовой базы для отправки в ИИ.
- `filter_setup_service.py`: Управляет логикой фильтрации файлов.

## 🔄 Поток управления (Control Flow)

1.  **Запрос от клиента:** `main.py` получает запрос на анализ через MCP.
2.  **Сессия:** `AnalysisSessionManager` создает новую или загружает существующую сессию.
3.  **Оркестрация:** `AnalysisAgent` получает управление. Он собирает контекст, формирует промпт с учетом истории диалога и отправляет его в ИИ через `ai_utils.py`.
4.  **Ответ ИИ:** `AnalysisAgent` получает и валидирует структурированный JSON-ответ.
5.  **Выполнение действий:** Если ИИ предложил изменения кода, `AnalysisActionExecutor` безопасно выполняет их, предварительно создав бэкапы.
6.  **Ответ клиенту:** Сервер возвращает клиенту структурированный ответ о статусе анализа, находках и выполненных действиях.

## 🧪 Тестирование

Для обеспечения надежности новой архитектуры была создана комплексная система тестирования с использованием `pytest`.

- **Структура:** Тесты разделены на `unit`, `integration` и `regression`.
- **Покрытие:** Основные компоненты, такие как `BaseSessionManager`, `ai_utils` и логика обработки ошибок, имеют 100% покрытие юнит-тестами.
- **Регрессия:** Специальные тесты гарантируют, что исправленные "тихие отказы" не появятся снова.
- **Запуск:** `uv run python -m pytest tests/`

## 🔮 Направления развития

- **AST-based рефакторинг:** Использование Abstract Syntax Tree для более безопасного и интеллектуального изменения кода.
- **Расширение набора действий:** Добавление новых команд для `AnalysisActionExecutor` (например, автоматическое исправление ошибок линтера).
- **Интеграция с CI/CD:** Запуск анализа в рамках CI/CD пайплайнов для автоматического ревью кода.
- **IDE плагины:** Создание плагинов для популярных редакторов для более тесной интеграции.

## Архитектура Neira Code Analyzer

## Обзор

Neira Code Analyzer - это MCP (Model Context Protocol) сервер для продвинутого анализа кодовых баз. Проект использует гибридную архитектуру Python + Rust для оптимального сочетания удобства разработки и производительности.

## Архитектурная схема

```
┌─────────────────────────────────────────────────────────────┐
│                    MCP Client                                │
│                 (Claude, Cursor, etc.)                      │
└─────────────────────┬───────────────────────────────────────┘
                      │ MCP Protocol
                      │
┌─────────────────────▼───────────────────────────────────────┐
│                 Python MCP Server                           │
│  ┌─────────────────┬─────────────────┬─────────────────┐    │
│  │   main.py       │   tools/        │   core/         │    │
│  │   (MCP Server)  │   (MCP Tools)   │   (Business)    │    │
│  └─────────────────┼─────────────────┼─────────────────┘    │
│                    │                 │                      │
│  ┌─────────────────▼─────────────────▼─────────────────┐    │
│  │            Service Layer                             │    │
│  │  • context_generator.py                             │    │
│  │  • docs_agent.py                                    │    │
│  │  • ai_utils.py                                      │    │
│  └─────────────────┬─────────────────────────────────────┘  │
└─────────────────────┼─────────────────────────────────────────┘
                      │ subprocess/FFI
                      │
┌─────────────────────▼─────────────────────────────────────────┐
│                 Rust Component                               │
│                 code2prompt_rs                               │
│  • Высокопроизводительный анализ файлов                     │
│  • Генерация контекста                                       │
│  • Обработка больших кодовых баз                            │
└─────────────────────────────────────────────────────────────┘
```

## Компоненты системы

### 1. MCP Server Layer (`src/neira_code_analyzer/main.py`)

**Назначение**: Точка входа MCP сервера, регистрация и обработка MCP инструментов.

**Ключевые особенности**:
- Регистрация 14 MCP инструментов
- Обработка MCP протокола
- Централизованное логирование
- Обработка ошибок на уровне протокола

**Зарегистрированные инструменты**:
- `get_context` - Генерация контекста для анализа
- `get_analyze` - Автоматический AI анализ
- `set_filters` - Настройка фильтров
- `get_templates` - Получение шаблонов
- `manage_presets` - Управление пресетами
- `gen_docs` - Генерация документации

### 2. Service Layer

#### context_generator.py
- **Назначение**: Генерация контекста для AI анализа
- **Функции**: 
  - Применение фильтров к файлам
  - Подсчет токенов
  - Интеграция с шаблонами
  - Вызов Rust компонента

#### docs_agent.py  
- **Назначение**: Автоматическая генерация и обновление документации
- **Функции**:
  - Сканирование существующих документов
  - Извлечение знаний из отчетов анализа
  - Обновление CHANGELOG
  - Архивирование обработанных файлов

#### ai_utils.py
- **Назначение**: Утилиты для работы с AI моделями
- **Функции**:
  - Интеграция с Google AI (Gemini)
  - Управление сессиями анализа
  - Обработка токенов и лимитов

### 3. Новые компоненты (недавно добавленные)

#### error_handling.py
- **Назначение**: Централизованная обработка ошибок
- **Функции**: Кастомные исключения, стандартизация ошибок

#### path_validator.py
- **Назначение**: Валидация путей и безопасность
- **Функции**: Проверка существования, доступности путей

#### service_container.py
- **Назначение**: Dependency Injection контейнер
- **Функции**: Управление зависимостями, конфигурация

### 4. Rust Component (`code2prompt_rs`)

**Назначение**: Высокопроизводительная обработка файлов и генерация контекста.

**Преимущества Rust компонента**:
- **Производительность**: В 10-100 раз быстрее Python для обработки больших файлов
- **Безопасность памяти**: Отсутствие memory leaks
- **Concurrent processing**: Параллельная обработка файлов
- **Низкое потребление ресурсов**: Оптимизация для работы с большими кодовыми базами

## Поток данных

### 1. Анализ кода (`get_analyze`)
```
MCP Client → main.py → analyze_code_tool → 
set_filters → context_generator → code2prompt_rs → 
AI анализ → сохранение результата
```

### 2. Генерация контекста (`get_context`)  
```
MCP Client → main.py → get_context_tool → 
применение фильтров → code2prompt_rs → 
форматирование по шаблону → возврат контекста
```

### 3. Генерация документации (`gen_docs`)
```
MCP Client → main.py → gen_docs_tool → 
docs_agent → сканирование файлов → 
извлечение знаний → обновление документов
```

## Принципы архитектуры

### 1. Разделение ответственности (SoC)
- **MCP Layer**: Только протокол и регистрация инструментов
- **Service Layer**: Бизнес-логика и интеграции
- **Rust Component**: Критичные к производительности операции

### 2. Конфигурируемость
- Поддержка пресетов фильтров
- Настраиваемые шаблоны анализа
- Гибкие параметры генерации

### 3. Error Handling
- Многоуровневая обработка ошибок
- Graceful degradation при недоступности компонентов
- Детальное логирование для отладки

### 4. Extensibility
- Модульная архитектура позволяет легко добавлять новые инструменты
- Plug-in система для шаблонов
- Абстракции для различных AI провайдеров

## Зависимости и технологии

### Python стек
- **MCP SDK**: Протокол взаимодействия с AI клиентами
- **Pydantic**: Валидация данных и настроек
- **aiohttp**: Асинхронные HTTP запросы к AI
- **pathlib**: Современная работа с путями

### Rust стек  
- **code2prompt**: Высокопроизводительная обработка файлов
- **tokio**: Асинхронная runtime для Rust
- **serde**: Сериализация данных

### AI интеграции
- **Google AI (Gemini)**: Основной провайдер для анализа
- **Anthropic Claude**: Поддержка через MCP
- **OpenAI**: Готовность к интеграции

## Безопасность

### Валидация входных данных
- Проверка путей на directory traversal
- Валидация размеров файлов
- Фильтрация опасных паттернов

### Изоляция процессов
- Rust компонент запускается в отдельном процессе
- Ограничение ресурсов через subprocess
- Timeout для предотвращения зависания

### Управление секретами
- API ключи через переменные окружения
- Не логирование чувствительных данных
- Безопасное хранение конфигурации

## Масштабируемость

### Горизонтальная
- Stateless архитектура MCP сервера
- Возможность запуска нескольких инстансов
- Shared-nothing подход

### Вертикальная  
- Rust компонент эффективно использует все CPU cores
- Streaming обработка больших файлов
- Настраиваемые лимиты памяти

## Мониторинг и отладка

### Логирование
- Структурированные логи в JSON формате
- Разные уровни детализации
- Трассировка запросов через компоненты

### Метрики
- Время выполнения операций
- Использование памяти
- Статистика по типам файлов
