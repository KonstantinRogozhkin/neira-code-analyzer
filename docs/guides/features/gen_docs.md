# Команда gen_docs - Автоматическая генерация документации

## Назначение

Команда `gen_docs` автоматизирует полный цикл создания и обновления документации проекта по принципам @DOCS_MANAGER.md.

## Основные возможности

- 🔍 **Сканирование** - находит сырые материалы (отчёты, длинные файлы)
- 🧠 **Извлечение знаний** - выделяет ключевые моменты по принципу "проблема → решение → результат"
- 📝 **Структурирование** - создаёт правильную структуру docs/
- 🗜️ **Сжатие** - уменьшает руководства до целевой длины (≤150 строк)
- 📋 **Changelog** - автоматически обновляет из git-истории
- 🗃️ **Архивирование** - убирает обработанные файлы в docs/archive/

## Быстрый старт

### Стандартная генерация
```json
{
  "path": "/path/to/project",
  "docs_structure": "standard"
}
```

### Минимальная генерация
```json
{
  "path": "/path/to/project", 
  "docs_structure": "minimal",
  "update_changelog": false,
  "archive_processed": false
}
```

## Параметры

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `docs_structure` | Тип структуры ('standard' или 'minimal') | 'standard' |
| `scan_depth` | Глубина сканирования директорий | 3 |
| `max_file_size` | Макс. размер файлов для обработки (строки) | 400 |
| `archive_processed` | Архивировать обработанные файлы | true |
| `update_changelog` | Обновлять changelog | true |
| `git_scan_days` | Дни для анализа git истории | 14 |
| `compress_guides` | Сжимать длинные руководства | true |
| `target_guide_length` | Целевая длина руководств | 150 |

## Создаваемая структура

```
docs/
├── README.md              # Обзор документации  
├── changelog/             # История изменений
│   └── CHANGELOG.md
├── guides/                # Технические руководства
│   ├── architecture/
│   ├── features/
│   ├── ops/
│   └── setup/
├── help/                  # Помощь пользователям
└── archive/              # Архив обработанных файлов (в .gitignore)
```

## Принципы работы

1. **"Provide as little context as possible, but as much as necessary"**
2. Сохранять только ключевые знания: проблема → решение → результат
3. Сжимать до сути, убирая историю и повторы
4. Структурировать для удобства навигации
5. Автоматически поддерживать актуальность

## Примеры использования

}
