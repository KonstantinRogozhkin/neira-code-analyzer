# Руководство по контрибьюции

Мы рады вашему интересу к проекту **neira-code-analyzer** и приветствуем любой вклад. Чтобы процесс был максимально гладким, пожалуйста, следуйте этим рекомендациям.

## 🐛 Как сообщить об ошибке

- Убедитесь, что ошибка еще не была зарегистрирована в разделе [Issues](https://github.com/your-repo/neira-code-analyzer/issues).
- Если вы не нашли похожей проблемы, создайте новый `issue`.
- Подробно опишите шаги для воспроизведения ошибки, ожидаемое и фактическое поведение.
- Приложите логи, скриншоты и версии используемого ПО.

## ✨ Как предложить улучшение

- Создайте новый `issue` с подробным описанием вашего предложения.
- Объясните, какую проблему решает ваше улучшение и почему оно будет полезно.

## 💻 Процесс разработки

1.  **Форкните** репозиторий.
2.  Создайте новую ветку для ваших изменений (`git checkout -b feature/amazing-feature`).
3.  Внесите изменения и напишите тесты, если это необходимо.
4.  Убедитесь, что все тесты проходят.
5.  Сделайте коммит с понятным и описательным сообщением (например, `feat: Add new analysis module`).
6.  Отправьте изменения в свой форк (`git push origin feature/amazing-feature`).
7.  Создайте **Pull Request** в основной репозиторий проекта.

## ☑️ Стиль кода и коммитов

- Придерживайтесь стиля кода, принятого в проекте.
- Старайтесь следовать правилам именования коммитов [Conventional Commits](https://www.conventionalcommits.org/). Это помогает автоматизировать создание списка изменений.
    - **feat:** для новых возможностей.
    - **fix:** для исправления ошибок.
    - **docs:** для изменений в документации.
    - **style:** для форматирования кода.
    - **refactor:** для рефакторинга без изменения функциональности.
    - **test:** для добавления или исправления тестов.

Спасибо за ваш вклад!
